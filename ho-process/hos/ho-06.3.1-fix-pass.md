# ho-06.3.1 — Fix pass for The Documents

ho-06.3x run 1 returned ho-06.3 with three Must-fix findings and three Notes. Everything ho-06.3 states still binds; where it differs from this document, this one does.

## Problem

From `ho-process/reviews/ho-06.3x-report-1.md`:

- **M1.** `README.md` and `TECHNICAL.md` say a command that starts with a space is kept nowhere. `History.record` judges each line of a submission on its own (`Sources/Hitoiki/History.swift:55-65, 108-112`), by design and under test (`HistoryTests.spaceRule`): in a command of several lines, a line without the space is kept. The claim is false for a command of several lines.
- **M2.** ho-06.3 Decision 5 lists "relaunch re-reads the environment (and Refresh Environment)" among the README's items. There is no Refresh Environment button; relaunch is the only way (K2's earlier amendment). The parenthesis is the spec's error, and the README is right not to name a button that does not exist.
- **M3.** The review's own guest run lost SSH to the guest during `swift test`, so the second test target, the coverage floor and the release build went unrecorded in that run.

The Notes (the edit-key table in two windows, two comments that name their selectors, tests that send events to the window rather than through the system) are judgments the review leaves to the practitioner; they stand.

## Solution

1. **M1.** Both documents state the rule as the code has it. README: "A line that starts with a space is kept nowhere; in a command of several lines, each line is kept or left on its own." `TECHNICAL.md`: "A command of several lines is kept line by line. A line that starts with a space, or is blank, is kept nowhere; the other lines of the same command are kept." The code does not change: the per-line rule is ho-05.2's, tested. The settings window's one-line hint, "Commands that start with a space are not kept.", is true of a one-line command and stays.
2. **M2.** ho-06.3 Decision 5's item reads: relaunch re-reads the environment. "(and Refresh Environment)" is struck; the README needs no change.
3. **M3.** Not a defect in the code. The orchestrator's guest runs at `66d79c3`'s tree (`20261114T203354Z`) and at `ae30a07` (`20261115T014554Z`) are six green, 215 app / 71 core tests in both steps, 95.76% / 98.25%; the tree under test has not changed since. The orchestrator runs `scripts/vm-test.sh` once more at this pass's commit, and run 2 runs it again.

Made by the orchestrator: two sentences in two documents, and this record. No builder; no code.
