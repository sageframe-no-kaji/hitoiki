# ho-02.1 — Fix pass for Run

ho-02x run 1 returned ho-02 with four Must-fix findings and one Should-fix. This ho answers them, takes two of the three Notes, and nothing else. ho-02's spec stays the record of what ho-02 did; its Reflect gets a one-line note pointing here. The practitioner's rulings, 2026-10-26: the Should-fix is fixed as well; keystrokes that cannot be written yet are held, not dropped; output is bounded by backpressure on the command, not by dropping bytes.

## Problem

From `ho-process/reviews/ho-02x-report-1.md`, each confirmed by the orchestrator against the code:

- **M1.** `LoginEnvironment.capture` enforces the five-second limit only while reading the pipe. Once the shell closes its output, `waitUntilExit()` waits without a limit, so a shell that closes stdout and keeps running gets past the deadline. The spec requires the whole capture to finish within five seconds and to throw `timedOut` when it does not.
- **M2.** `Run.write` writes to the pseudoterminal on the actor's own serial queue. When the child stops reading and the kernel's input buffer fills, the write blocks that queue, and `interrupt()` and `kill()` cannot run until the child reads or exits. Both cancellation paths are lost for the duration. ho-02's Reflect recorded this as a behaviour; it is a defect.
- **M3.** `bytes` is an `AsyncStream` with an unbounded buffer and `readChunk` enqueues without regard to the consumer. A command that produces output faster than the consumer takes it grows memory without a ceiling. The seed requires a bounded footprint for output; Transcript's ceiling (ho-04) bounds what is kept after consumption and cannot bound this queue upstream of it.
- **M4.** The driver restores the terminal only after the normal Done wait and handles `SIGINT` alone. `SIGTERM` or `SIGHUP` ends it with the terminal left raw. The spec requires restoration on every exit path.
- **S1.** Releasing a Run while a command is alive finishes the two streams and nothing else: the dispatch sources are not cancelled, the pseudoterminal stays open, the child keeps running and is never reaped. The seed says no command continues after dismissal; an app quitting mid-command would leak the process.

Also taken in from the same review: **N2**, three comments that restate their declarations (`WindowSize.init`, `Exit.status`, `RefusalScanner.sawRefusal`); **N3**, two specified refresh behaviours with no test (the captured environment is what the next command runs with; on a failed capture the old environment is kept). N1, the duplicated write loop in the driver, is left: the driver is deleted at ho-03.

## Solution

**M1 — the deadline covers the wait.** After the pipe reaches end of output, `capture` waits for the shell to exit only until the same deadline, polling `isRunning` at 10 ms. If the deadline passes first, the shell is killed with `SIGKILL`, reaped, and `timedOut` is thrown, exactly as the read path does. Test: a fake shell that prints one variable, closes its stdout (`exec >&-`), and `exec`s `/bin/sleep 30`; the capture throws `timedOut` between five and eight seconds after it started.

**M2 — writes never block the actor.** The parent sets the primary descriptor non-blocking after `forkpty`. `write` appends to a pending byte buffer held by the live `Child` and flushes as much as the kernel accepts; what remains is written when a dispatch write source on the primary fires, in order, until the buffer is empty. The write source exists only while bytes pend (created on the first short write, cancelled when drained), so the suspend/resume balance of dispatch sources is never in play. `interrupt` and `kill` are unaffected by pending bytes; pending bytes are discarded at Done. One consequence for reading: with the descriptor non-blocking, `read` can return `EAGAIN`, which is "nothing now", not end of output; `readChunk` treats it as it treats `EINTR`. Tests: (a) a child that runs `stty -icanon -echo; echo ready; sleep 4` and never reads; after `ready` the test writes 262,144 bytes through Run and calls `kill()` at once; Done arrives as `.signal(SIGKILL)` within one second of the kill, and the group is empty. (b) a child that runs `stty -icanon -echo; echo ready; sleep 1; head -c 70000 | wc -c`; the test writes 70,000 bytes after `ready`; the output contains `70000`. Nothing in the keystroke test changes: `hunter2` still never appears in the output.

**M3 — backpressure.** `bytes` becomes `Run.Output`, an `AsyncSequence` of `[UInt8]` over a private chunk stream. Its iterator reports each chunk taken to the actor, which counts unread bytes across commands. Each read is limited to the room under a constant 1 MiB ceiling (`Run.outputCeiling`, internal, not configurable); at the ceiling the read source suspends, so the kernel's pseudoterminal buffer fills and the command blocks on its next write. Consumption resumes the source when there is room. A new child's read source starts suspended if the queue is already full. Reaping records the exit; the same read source drains the terminal within the ceiling before close and Done. A suspended source is resumed before cancellation, since releasing one traps. The iterator holds Run weakly; releasing Run finishes the stream after its queued chunks, and the sequence stays open between commands. Nothing is dropped. Tests: an 8 MiB producer stays alive while consumption is delayed, then every byte is consumed and Done is `.status(0)`; repeated short commands stop completing when unread output fills the queue, then resume without losing bytes when consumption starts. The driver and existing tests consume the new sequence.

**M4 — the driver restores on every signal.** The driver's signal stream takes `SIGTERM` and `SIGHUP` as well as `SIGINT`. On either of the two, it restores the terminal, kills the command, waits for Done, and exits with 128 plus the signal. Demonstration, recorded in Results: under `script -q /dev/null`, start `issoku-run -- 'sleep 30'`, send it `SIGTERM` after one second, and show `stty -a` afterwards reports `echo` and `icanon` on.

**S1 — release cleans up.** `deinit`, when a child is alive: send `SIGKILL` to the owned pid and group, resume the read source if suspended, cancel the read, write and exit sources, then reap the child with `waitpid`. The read source's cancel handler closes the captured descriptor without retaining Run. Finishing the private byte stream wakes its waiting iterator and preserves queued chunks; the state stream finishes too. A refresh waiting for Done retains Run until it returns. Tests release a Run with a sleeping child and with output paused, then inspect the process table for the pid and group.

**N2.** The three declaration-restating comments are removed. `WindowSize.init` retains a comment explaining why its pixel dimensions are left zero.

**N3 — refresh is tested.** Run gains an internal initializer parameter, `captureShell: String? = nil`, passed through to `LoginEnvironment.capture(shell:)` by `refreshEnvironment`; it is internal, reachable by the tests through `@testable import`, and not part of the public surface. Tests: (a) a fake shell that prints `FROM_REFRESH=1` and nothing else; after `refreshEnvironment()`, a command that runs `echo $FROM_REFRESH $TERM` prints `1 xterm-256color`. (b) a fake shell that exits 3; `refreshEnvironment()` throws `shellFailed(status: 3)` and a command run afterwards still sees a variable from the original environment.

**M3 correction during verification.** Draining beyond the ceiling after reap would let successive completed commands accumulate unread output. A regression primed the queue to 256 bytes below 1 MiB, then ran 64 commands producing 256 bytes each. The regression consumes all 1,064,704 zero bytes and observes all 65 successful completions. The 8 MiB case delays consumption for five seconds, longer than this machine's roughly three-second unbounded transfer, then receives every byte.

Input waits in the child's pending buffer until the terminal accepts it or the command ends. Signaling falls back to the owned pid when the child's process group has not yet been created.
