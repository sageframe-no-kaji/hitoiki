# ho-05.2 — History

The second ho of Phase 3, and the last before the ship. ho-05.1 built everything in user defaults and left `historyEnabled` stored and read by nothing. This ho builds everything that lives in the history file, and the ways back to a command already run.

What the user gets. With history on in settings, every command that runs is added to a plain text file they can open in TextEdit. In the panel, Down-arrow opens a list of past commands under the input, newest first, ten rows at a time; typing narrows it. As they type, the rest of the newest matching command shows in grey after the cursor, and Right-arrow takes it. Choosing from the list or taking the suggestion puts text in the input; only Return runs it. With history off, the same list and suggestion work from the commands run since launch. Clear History in settings deletes the file and forgets the session. A command typed with a space in front runs and is kept nowhere.

**Out of scope:** output history by scrolling and a Clear button on the panel (refused 2026-11-05, not reopened); a control on the bar (dropped in this Think, Decision 8); the update checker, About, Check for Updates (ho-06); the README (ho-06, which takes the space rule, Decision 12); transcript storage; any file but the history file; any persisted key beyond ho-05.1's ten; any dependency in `Package.swift`; any change under `Sources/HitoikiCore/`.

**Resolves** the overview's two decisions for this ho: "History write timing and duplicates" (Decisions 1, 2) and "The bar control's shape" (Decision 8: there is none; the list drops from the input).

**Scope changed in the Think, by the practitioner's rulings of 2026-11-10.** Added: search in the list (Decision 7), the grey suggestion (Decision 8), the space rule (Decision 12), Command-Q in the settings window (Decision 11). Dropped: the control on the bar (Decision 8). Changed: Clear also forgets the session (Decision 9), so ho-05.2x's last question becomes "does recall then show nothing until the next command runs?". The overview's ho-05.2 entry gets a dated note pointing here. K2 §2.4 gets one amendment note (see Changes).

**Carried in.** From ho-05.1's second run sheet: the macro rows' spacing; the Quit button at the foot of settings removed. From ho-05.1x run 2: N10, Caps Lock blocks Command-C, V, X and A in the input.

## Phase 1 — Think

Twelve questions, settled with the practitioner on 2026-11-10, one at a time.

### Decision 1 — The file, and what goes in it: what ran, one line each

The file is `~/Library/Application Support/Hitoiki/history.txt`, UTF-8, one command per line, each line ending in a newline. The folder is made at the first write with permissions 0700 and the file with 0600, so only the user can read it; an existing file's permissions are left as they are. It is the only file in that folder and the only file the app writes. Settings stay in user defaults.

What is written is what ran: the line handed to `Run.start`, so a blank Return or Retry that takes the `-tt` offer writes `ssh -tt …`, and the `ssh …` that failed before it was written when it ran. A line is written when Run reports Running for its submission; a start that fails before Running ran nothing and writes nothing. Only a submission starts a command, so the file is written at Return (or Retry) and at no other moment.

A submission of several lines (Shift-Return or Option-Return) writes each line as its own entry, in order; a line with `&&` or `;` is one entry because it is one line. Lines empty or only whitespace are skipped. The practitioner was told that a block's lines come back separately; the ruling stands.

Turning history on writes only commands that start after it is on; the session's earlier commands are not copied in. Turning it off writes nothing more and deletes nothing.

If the existing file does not end in a newline (edited by hand), the append starts with one. A write that fails puts one line on the notice, "History not saved: <reason>", once; a repeat of the same failure adds nothing.

### Decision 2 — Repeats: the file keeps them, recall shows each once

The file keeps every line, repeats included, in the order they ran. Recall shows each command once, at its newest place. Two entries are the same when their text matches exactly after leading and trailing whitespace is ignored.

### Decision 3 — Reads: fresh each time, nothing kept

The file is read whenever the list or the suggestion needs entries: when the list opens, at each keystroke that changes the filter, and at each keystroke that changes the suggestion. Nothing read from the file is kept between reads, so a line deleted in TextEdit is gone from the next keystroke's recall, and Clear needs no second step. A missing file is an empty file. A file that exists but cannot be read gives the session alone and one notice line, "History could not be read: <reason>", once.

(The practitioner agreed to "read when recall starts"; reading at every keystroke is the same rule with no walk state, at a cost of reading at most 5,000 lines, well under a millisecond's concern. Named here for his approval of the spec.)

### Decision 4 — The ceiling: 5,000 lines, trimmed at Return

The file holds at most 5,000 lines. After a write, if it holds more, the newest 5,000 are written to a new file beside it and swapped in, in one step (`Data.write(to:options: .atomic)`), so a crash never leaves half a file. The trim happens only inside the write at Return. Session memory holds at most 5,000 commands too, oldest dropped first.

bash keeps 500 by default and macOS's zsh 1,000; the practitioner chose 5,000.

### Decision 5 — The list: Down-arrow opens it below the input, newest first

One list of entries: this session's commands, newest first; then, with history on, the file's, newest first; each command once (Decision 2). With history off, the session alone.

- **Open.** Down-arrow in the input opens the list with the top row selected. It opens only when the cursor is on the input's last line; otherwise Down-arrow moves the cursor as in any text field. The list never opens while a command runs or a submission is in flight.
- **Move.** Down moves the selection older; Up moves it newer; Up from the top row closes the list.
- **Choose.** Return, or a click on a row, puts the entry in the input and closes the list. Nothing runs; a second Return runs it.
- **Escape** closes the list and changes nothing else. The next Escape is the ladder's (ho-04.6).
- **Close by moving.** Anything that hides or clears the panel, or starts a command, closes the list.
- **Show.** Ten rows visible, the rest by scrolling. Each row is one command on one line in the transcript's monospaced font, a long command cut with "…" at its end. The selected row is marked in the accent colour. Empty: one faint row, "No commands yet" with nothing typed, "No match" with text typed; Return then closes the list and runs nothing.
- **Where.** A borderless child window of the panel, with the panel's card look (ground, corner radius 10, hairline), the cards' width, its top just under the bar card. It lies over whatever is below, the output card included, and the panel does not move or resize. It never takes the keyboard: the input keeps it the whole time, so typing goes on into the input and the click-out rule (which hides the panel when it loses the keyboard) never fires from a click on the list.

The practitioner reversed the shell convention: the input is at the top of the panel and the list hangs below it, so down is older.

### Decision 6 — Down-arrow on a multi-line input: only from the last line

As Decision 5's Open. The input's last line is also what the list filters by and what a choice replaces (Decision 7).

### Decision 7 — Search: the list filters by what is typed

While the list is open, it shows the entries that contain the input's last line anywhere, upper and lower case alike: `host` finds `ssh host-a uptime` and `ping HOST-b`. Every keystroke that changes the text re-filters, and the selection returns to the top row. An empty last line shows every entry. Typing alone never opens the list. Choosing replaces the last line with the entry; on a one-line input that is the whole input. The cursor ends at the end of the text. The matched part is not marked.

The overview offered no search; the practitioner added it ("cheap and powerful").

### Decision 8 — No control on the bar; the grey suggestion

**No bar control.** Down-arrow does what the control would; the bar stays the input and the gear.

**The suggestion.** After a keystroke that changes the input's text, if the cursor is at the end of the text, the last line is not empty, and some entry starts with that line exactly (case and all) and is longer than it, the rest of the newest such entry is drawn after the cursor in the faint ink colour. The typed text keeps its own colour; only what lies beyond it is grey. The grey text is drawn, not typed: it is not in the input's value, Return runs only the real text, and Command-C and Command-A never reach it. Right-arrow with the cursor at the end takes it into the input; otherwise Right-arrow moves the cursor as usual.

It is not shown while the list is open, while a command runs, when the cursor is not at the end, after a load (a list choice, a macro, a taken suggestion), or after a clear. Grey text wider than the input is cut at the input's edge; taking it adds the whole entry.

Case-sensitive, unlike the list's filter, because taking it joins the typed text to the entry's rest: `SSH h` taking `ost-a` from `ssh host-a` would make a command no one ran.

### Decision 9 — Clear: the file and the session

A button, "Clear History…", on the row under the "Keep a history of commands" switch. It asks once: "Delete your command history? This can't be undone.", with Cancel and Delete. Delete removes the file and empties session memory; the list and the suggestion then show nothing until a command runs. It works with history off, so a file left from before can go. Nothing else is deleted: not the folder, not a setting.

The overview's review question assumed the session survives Clear. The practitioner chose otherwise: a Clear that leaves down-arrow showing the command typed five minutes ago looks broken, and a token typed in a command is in session memory too.

### Decision 10 — N10: Caps Lock no longer blocks Command-C, V, X, A

`PanelWindow.performKeyEquivalent`'s editing route compares the four modifier keys, as the macro and Command-Q routes do since ho-05.1.1, not the whole flag mask. A test presses each of the four with Caps Lock on.

### Decision 11 — Quit: the button goes, Command-Q works in settings

The Quit button and the divider above it leave the foot of settings (ho-05.1 run sheet 2). Command-Q quits while the panel has the keyboard (as now), from the menu bar item's menu (as now), and, new, while the settings window has the keyboard, through the same path: the application's terminate, whose delegate kills a running command first. K2 §2.1's amendment of 2026-11-10 named a Quit button at settings' foot; this ho's K2 note records it gone.

### Decision 12 — The space rule: a line that starts with a space is kept nowhere

A line that starts with a space runs as typed and is written to neither the file nor session memory, so the list and the suggestion never show it. Checked per line, at the moment of writing (Decision 1). It is how a command with a secret in it runs with history on.

The practitioner asked that it be documented. Two places: a caption under the history switch in settings, "Commands that start with a space are not kept."; and the README, which ho-06 writes (added to ho-06's carried list at this ho's close).

### Carried — the macro rows' spacing

The nine macro rows stand closer: the run sheet found them too loose. The builder reduces each row's vertical padding so the nine rows take visibly less height, records each row's height before and after in its report, and the practitioner's run sheet judges it.

### Decision 13 — One builder, the ho document as spec

One Opus builder. The list, the suggestion and the file all meet in `Panel.swift` and `PanelWindow.swift`; a second builder would collide. No agent-task files.

`History.swift` is the file, the session, the entries, the filter, the suggestion and the space rule, with no AppKit: measured by the floor. `RecallList.swift` is the child window and its rows: measured, since a child window can be made and driven in the guest; if the builder finds a part that cannot be driven without a screen, that is a halt and report, not an exclusion. `SettingsView.swift` stays excluded.

### Decisions from the practitioner's run sheet, 2026-11-10

The run sheet on the release build of `c7880f8` passed all twelve items. Three changes were ruled, each a decision here as in ho-05.1, made by a second builder pass before the Reflect.

### Decision 14 — In settings, Command-1 to Command-9 go to that macro's box

With the settings window in front, Command-N puts the keyboard in macro N's box with the cursor at the end of its text, nothing selected. Nothing runs and nothing else changes. The four modifier keys alone decide it, so Caps Lock does not block it. In the panel, Command-N still loads the macro into the input (ho-05.1 Decision 8); the practitioner considered having it run at once and chose this instead, so the macro rule stands.

### Decision 15 — Command-comma opens settings from the panel

Command-comma, the Mac's own key for Settings, opens the settings window from the panel in every state, as the gear's click does and by the same route. Caps Lock does not block it. In the settings window it does nothing. Command-S is not used.

### Decision 16 — The macro rows: no dividers, 32 points apart

The grouped form's divider lines are hidden between the nine macro rows only; every other section keeps its dividers. The rows stand 32 points apart (38 after the first pass, 48 before this ho), a 5-point gap between the 27-point boxes. The builder measures the spacing before and after, and the test that guards it checks 32. If the grouped form will not hide the dividers, that is a halt and report, not a workaround.

**Tests for these.** Command-1 in the settings window puts the keyboard in macro 1's field editor with the cursor at the end, and Command-9 in macro 9's, in the settings-window suite. Command-comma on the panel sends `showSettings` without the gear, witnessed by a stand-in or by the window opening in the settings-window suite, in every state including Running, with Caps Lock on too; Command-comma in the settings window does nothing. `macroRows` checks 32 points. The dividers' absence is witnessed live only.

## Phase 2 — Execute

### Vocabulary

- **The file**: `history.txt` of Decision 1. In tests, a file in a throwaway folder handed in at init.
- **Session memory**: the commands run since launch, held by `History` in process memory, at most 5,000.
- **Entries**: session newest first, then (history on) the file newest first, each command once.
- **The list**: Decision 5's child window. **Open** / **closed**.
- **The suggestion**: Decision 8's grey text.
- **The last line**: the input's text after its last newline; all of it on a one-line input.
- **A load**: text put in the input by anything but a typed key: a list choice, a taken suggestion, a macro.

### Invariants

1. Nothing recalled runs. A list choice, a taken suggestion and the list's opening change the input's text and nothing else; only Return or Retry submits, and they submit the input's value, which never holds grey text.
2. The file is written only when a command starts running, and holds exactly the lines that ran with history on, in order, minus those that start with a space and those empty or whitespace-only. With history off it is never created, opened for writing or changed.
3. The file never holds more than 5,000 lines after a write, and the lines kept are the newest.
4. No file is written but the history file (and the atomic rewrite's transient file, Discovery 2). No new key in user defaults.
5. Entries are the session's commands newest first, then the file's newest first when history is on, each once by Decision 2's sameness; the session alone when off.
6. Every recall reads the file fresh; a change to the file outside the app shows at the next keystroke.
7. After Clear, the file does not exist and entries are empty until a command runs.
8. The list never takes the keyboard: the panel stays the key window while the list is open, through clicks on it.
9. The list is never open, and the suggestion never shown, while a command runs or a submission is in flight.
10. The filter is a case-insensitive contains on the last line; the suggestion is a case-sensitive starts-with, newest first, strictly longer.
11. Escape with the list open closes it and changes nothing else; with the list closed, the ladder is unchanged.
12. Command-C, V, X and A act the same with Caps Lock on as off. Command-Q quits from the settings window.

### Tests

Both suites run in the guest through `scripts/vm-test.sh`. The builder writes them from the invariants, not the implementation, and derives every expected value from an invariant. The partitions below are the ones the orchestrator reads for; each invariant has at least one.

**`Tests/HitoikiTests/HistoryTests.swift`** (new), over a throwaway folder, no AppKit:
- Writing: history on, three lines run, the file holds the three in order with newlines; history off, nothing run creates the file; a multi-line submission writes each non-empty line; a line starting with a space is in neither the file nor the entries, and its neighbours in the same block are; a file without a final newline gets one before the append; the folder is made 0700 and the file 0600 when absent.
- The ceiling: a file of 5,000 lines plus one write holds 5,000, the oldest gone, the new one last; a file of 4,999 plus one holds 5,000 unchanged in its first line; session memory past 5,000 drops its oldest.
- Entries: session before file; newest first in each; a command in both appears once at its session place; `df -h` and ` df -h ` (spaces at the ends) are one; history off gives the session alone though the file has lines.
- Reads: a line removed from the file by the test between two reads is gone from the second; a missing file gives the session alone and no notice; an unreadable file (permissions 000) gives the session alone and one notice line.
- Filter: contains, either case; empty filter gives all; no match gives none.
- Suggestion: newest starts-with wins; case must match; an entry equal to the text gives none; empty text gives none.
- Clear: the file is gone, entries are empty, a command run afterwards is the only entry.
- A write that fails (the folder made read-only by the test) puts one notice line, and a second failure adds none.

**`Tests/HitoikiTests/PanelTests.swift`** (extended):
- The write moment: a command that runs is written; a submission whose start fails is not; the `-tt` offer taken by blank Return writes the `ssh -tt …` line.
- The list: Down-arrow on an empty input opens it with the top row selected; Down, Down, Return puts the third entry in the input, state still nil, no child in the process table (invariant 1); Up from the top closes it; Escape closes it with the input unchanged, and a second Escape clears by the ladder; Down-arrow on a two-line input with the cursor on the first line moves the cursor and opens nothing; typing with the list open narrows it and returns the selection to the top; "No match" then Return leaves the input as it was and runs nothing; a click on a row loads it and the panel is still the key window (invariant 8); hide with the list open closes it; Down-arrow while Running opens nothing and writes nothing to the pseudoterminal.
- The suggestion: after typing a prefix, the input's value is the typed text only; Right-arrow at the end makes the value the whole entry and runs nothing; Return with a suggestion showing runs the typed text only; no suggestion after a macro load or a list choice; none while the list is open; none with the cursor moved left.
- N10: Command-C, V, X, A with Caps Lock on, each with its effect, by the pattern of ho-05.1.1's Caps Lock tests.

**`Tests/HitoikiTests/SettingsTests.swift`** (extended):
- Command-Q in the settings window reaches the terminate selector, witnessed unsent by a stand-in, as `commandQuit` does.
- The defaults domain after the suite still holds no key outside ho-05.1's ten.
