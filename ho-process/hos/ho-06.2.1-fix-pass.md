ho-06.2x run 1 returned ho-06.2 with four Must-fix findings and one Note. The orchestrator read each against the code on 2026-11-14. Everything ho-06.2 states still binds; where the two differ, this one does. This spec states what must hold and prescribes no mechanism beyond it.

## Problem

From `ho-process/reviews/ho-06.2x-report-1.md`:

- **M1.** `offerWritten` (`Tests/HitoikiTests/PanelRecallTests.swift`) timed out once in the reviewer's ordinary test step and passed in its coverage step; it passed in both steps of the builder's and the orchestrator's runs. Its body is unchanged from before the move. `until` throws a bare `TimedOut()`, so the log names the test but not the wait, and the cause cannot be read.
- **M2.** F1's test drives `Panel.killForQuit()` only; `App.applicationShouldTerminate` reads `panel.isBusy || panel.awaitsClearedDone` itself, so reverting the app's guard alone would pass every test. The same condition is written three times (`App.swift:94`, `Panel.swift:279` and the wait at `:282`).
- **M3, M4.** F3 (the history test's watcher) and F5 (the core coverage gate) have no test that fails on the old code, as ho-06.2's builder rule asks of every ruled bug. Ruled below.
- **N1.** Decision 15's wholly evicted selection has no test.

## The practitioner's ruling, 2026-11-14

**On M3 and M4.** The failing-first test applies to bugs in the app. A bug in test code or a script is witnessed by a demonstration recorded in the spec, not by a permanent test: no tests of test helpers, no harness for scripts. ho-06.2's builder rule and invariant 3 read so from now on. The demonstrations:

- **F5.** The gate's Python, run alone on an export with no files: the old snippet printed "nothing to measure yet" and exited 0; the new one prints "0.00% over 0 files" and exits 1. One file at 96% exits 0; one at 80% exits 1. (ho-06.2's builder, 2026-11-14.)
- **F3.** The event stream holds the watcher without retaining it. On the old path a failed wait skipped `stop()`, the test released the watcher, and the next file event read freed memory; a failed start left the stream unreleased. On the new path the stream is stopped in a `defer` taken as soon as the watcher exists, a failed start releases the stream before throwing, and `stop()` waits for queued callbacks before it returns.

## The invariants

1. **A test wait that times out names itself.** When a fixture wait gives up, the failure says which wait it was—its place in the test file—and what it was waiting for, so a timeout in the log can be read without re-running. No test's timeout changes length.
2. **Quit's rule is written once.** Whether Quit must wait—a command running, a start in flight, or a kill a clear sent whose Done has not arrived—is one property of `Panel`. `applicationShouldTerminate` and `killForQuit()` both read it, and the wait in `killForQuit()` waits on it. The F1 test asserts that property directly after a killing clear, so reverting either reader's use of it, or the property itself, fails a test.
3. **The wholly evicted selection.** A test selects lines that eviction then removes entirely, and witnesses that nothing is selected afterwards and that Copy takes the whole transcript.
4. **M1.** With invariant 1 in place, the builder's runs and the orchestrator's show whether `offerWritten` times out. If it does, the named wait is the evidence; the builder halts and reports it, and the orchestrator decides the fix. If it does not, the timeout is recorded here as not reproduced, with invariant 1 in place for the next one.
