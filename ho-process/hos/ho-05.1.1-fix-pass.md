# ho-05.1.1 — Fix pass for settings and macros

ho-05.1x run 1 returned ho-05.1 with one Must-fix, two Should-fix and nine Notes. The orchestrator read each against the code on 2026-11-10, unattended, under the practitioner's instruction of that day to continue through the review. This spec states what must hold, names where the code and the tests fall short of it, and prescribes no mechanism. Everything ho-05.1 states still binds.

## Problem

From `ho-process/reviews/ho-05.1x-report-1.md`, confirmed by the orchestrator against `8b38365`:

- **M1.** `PanelWindow.performKeyEquivalent` decides the macro route by comparing the event's device-independent flags whole with Command, and those flags carry Caps Lock, so with Caps Lock on Command-1 to 9 never reach `Panel.loadMacro`. The Command-Q route four lines below strips Caps Lock first. Decision 8 says the load happens in Composing and Done; it says nothing about the lock keys because it did not think of them. Every macro test builds its event with Command alone (`PanelTests.swift:1544`), so the tests pass with the action broken in that keyboard state.
- **S1.** `Tests/HitoikiTests/PanelTests.swift` imports `HitoikiCore` with `@testable`, added in the first pass for a fixture the second pass removed; nothing in the file reaches an internal core declaration now.
- **S2.** The same ten-second polling helper, `until`, is written out in `SettingsTests.swift` and `MenuBarItemTests.swift`.
- **N6.** Three comments say what the next line does and not why: `Settings.store`, `Terminals.installed`, `MenuBarItem.isShown`.
- **N7.** Both test builds warn at `SettingsTests.swift:259`: `'#require(_:_:)' is redundant because 'box' never equals 'nil'`.
- **N8.** ho-05.1's Reflect says the practitioner's `defaults read` showed "eleven keys from the table"; the table has ten and so did his output. A wrong count in a record, corrected as a typographical fix by the orchestrator.
- **N1, N2, N3, N4, N5, N9** stand as ho-05.1's Reflect recorded them; this pass changes none of them.

## The invariant

ho-05.1's ten invariants hold, with one sentence added to invariant 3.

**Invariant 3, a macro never runs**, now also reads: the macro route is decided by the four modifier keys, Control, Option, Shift and Command, and by nothing else the event carries. Command with a digit 1 to 9 loads the slot in Composing and in Done and does nothing while Running, whether Caps Lock is on or off; Command with any other modifier held is not the macro route. The partitions a test must cover: Caps Lock on in Composing (loads), Caps Lock on in Done (loads), Caps Lock on while Running (nothing changes, nothing reaches the command), and Option-Command-1 (not a macro, the input unchanged). The existing macro tests keep their Command-alone events.

The window's four editing equivalents (Command-C, V, X, A) decide the same way today and are not this pass's; the reviewer may name them.

## Solution

**M1.** The macro route reads the four modifier keys alone. The tests above, in `PanelTests`, beside the macro tests that exist; the Caps Lock event is built as `commandQuit` builds its own.

**S1.** The core import in `PanelTests.swift` is plain `import HitoikiCore`. If the build then fails on an internal core name, that name is the finding's answer and the builder halts and reports it rather than restoring `@testable`.

**S2.** One `until` helper, in the file that already holds the shared `ThrowawaySuite`, visible to both suites; the copy goes. `PanelTests`' `Fixture.until` is a method on the fixture and is not this pass's.

**N6.** Each of the three comments either says why the code is as it is or is deleted. `store` removes the key for nil so that an absent value reads as the default rather than as an empty string; `installed` keeps `known`'s order so Terminal.app leads the pop-up; `isShown` acts at once so the switch needs no relaunch. Those are the reasons if the builder keeps the comments.

**N7.** The warning goes by writing the test so the compiler's claim is true or the require is not redundant; the test still asserts that an editable box was found before Escape is sent. `swift build` and both test builds show no warning in the log.

**N8.** The orchestrator changes "eleven" to "ten" in ho-05.1's Reflect; a count, not a conclusion.
