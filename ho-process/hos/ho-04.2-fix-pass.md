# ho-04.2 — Second fix pass for Transcript

ho-04x run 2 returned ho-04 with three Must-fix findings, one Should-fix and one Note. This ho answers the four and nothing else. All three findings are the same shape: ho-04.1 bounded the model's work at moments that depend on where a feed ends, and the spec said so, while Decision 1 says state carries across feeds, so nothing the model reports may depend on where they end. ho-04.1's Results stay the record of what it did; they get a one-line note pointing here. This is the second Return on ho-04; a third stops the build for the practitioner by the standing checkpoint.

## Problem

From `ho-process/reviews/ho-04x-report-2.md`, each confirmed by the orchestrator against the code at `1b42564a4e50cde41dede933e2186eae189c24ff`:

- **M1.** The line in progress is trimmed to 1 MiB at the end of every feed, with the cursor moved by what was dropped. A carriage return after that trim lands on the first retained column; before it, on a column the trim then drops. So `1,048,576 x, 1,023 y, CR, Z, LF` commits a line beginning `xxxx` in 16,384-byte chunks and whole, and `Zxxx` in 1,024-byte chunks. ho-04.1 recorded the case as a residue; the reviewer rules, rightly, that a recorded violation of Decision 1 is still one.
- **M2.** After an ESC inside a control string, a BEL is read as more of the string, so `a ESC ] before ESC BEL b LF` commits nothing and holds `a`, for every one of the five introducers. Decision 1 ends the string at BEL; ho-04.1's wording ("any other byte returns to the string") was the orchestrator's error and the builder followed it.
- **M3.** `commit()` appends every line, and the line and byte ceilings are applied once the whole feed is parsed. A 50 MB feed of 500,000 short lines holds all 500,000 before the first eviction: the model's resident size grew by 130 MB in the reviewer's measurement. Run feeds at most 16 KiB at a time, which hides it in the app, but `feed` is public and the seed's fixed footprint is the model's promise, not the caller's.
- **S1.** No equivalence case contains a CR; the removed-sequence table has no ESC-then-BEL row; the ceiling measurements read the model only after each feed returns. Together they pass all three.

The Note (**N1**) keeps run 1's boundary: the cursor's drawing, the colours on screen, the wrap and the jiggle are witnessed by the run sheet, as the review brief says they may be. Nothing to do.

## Solution

**M1 — the line in progress is the newest 1 MiB of columns at every byte.** One definition replaces trim-at-moments: an origin index marks the first retained byte of the line in progress; the retained line is the bytes from the origin on; after every byte put, the origin moves forward until at most 1,048,576 bytes remain, by whole characters. Carriage return sets the cursor to the origin. `retainedBytes` counts from the origin. The arrays themselves are compacted, dropping everything before the origin, whenever the origin passes the 16 KiB slack and at the end of every feed, so the physical storage never holds more than the cap plus the slack and holds exactly the retained line between feeds; compaction never changes what is reported. The continuation-byte rule reads "joins the character before it" relative to the origin. After this, the reported line, the cursor and every commit are a function of the byte stream alone. Tests: the reviewer's probe fed whole, in 16,384-byte chunks and in 1,024-byte chunks commits the same line, beginning `Zxxx` (the overwrite lands on the first retained column in every partition); the ceiling-crossing equivalence case of ho-04.1 gains carriage returns and overwrites around each ceiling.

**M2 — BEL ends a control string even after an ESC.** In the control-string-escape state: backslash ends the string, BEL ends it, another ESC stays, any other byte returns to the string. The comment says so. Tests: `a ESC <i> before ESC BEL b LF` yields `ab` for all five introducers, as rows of the removed-sequence table.

**M3 — eviction as lines are committed.** `commit()` appends the line, then evicts from the top while the committed lines exceed 10,000 or the retained bytes exceed 10 MiB, counting what it dropped into the feed's running count; `feed` keeps its final check for the line in progress growing between commits. The retained bytes used by every check are the retained line's count from the origin, never the physical array's, so the eviction a check makes is the one the byte stream determines. `Change` keeps its contract: `evicted` counts lines dropped from those reported before the feed, `committed` lists the lines committed by the feed and still held. Test: a 50 MB feed of 500,000 lines of 99 `x` and LF, in one feed, returns 10,000 committed, 0 evicted, 990,000 retained bytes, the same `lines` as the same input in 16 KiB chunks; and the resident size of the test process, read from `mach_task_basic_info` before and after that one feed with the input allocated before the first reading, grows by less than 32 MiB (the reviewer measured 130 MB before the fix; the retained 10,000 lines are about 2 MB). The bound is wide because resident size is noisy, and narrow enough that holding the feed's lines would fail it.

**S1 — the tests cross the interactions.** The CR cases of M1, the ESC-then-BEL rows of M2, the one-feed ceiling case and the resident-size reading of M3.

## Results

Closed 2026-11-04. The ho-04 subagent, resumed, built the three fixes test first; the orchestrator read the whole diff, added one assertion, ran the six checks with the Transcript suite three times, and committed. The app was never launched.

**M1.** An `origin` index marks the first retained byte of the line in progress. `advanceOrigin()` runs after every byte put or joined and moves the origin forward by whole characters until at most 1,048,576 bytes remain, keeping the cursor at or after it; CR sets the cursor to the origin; the continuation-byte rule and `retainedBytes` read from the origin; `commit()` renders from it. `compact()` drops the bytes before the origin when it passes the 16 KiB slack and at the end of every feed, so between feeds the arrays hold exactly the retained line; `dropOldestColumns` is gone. `line()` takes slices. Tests: the reviewer's probe fed whole, in 16,384-byte and in 1,024-byte chunks commits the same 1,048,576-byte line beginning `Zxxx`; the ceiling-crossing case now carries a CR overwrite in every short line, every wide line, the 2 MiB line and the line in progress, fed whole, in 16 KiB and in 1 KiB chunks, with the overwritten prefixes asserted. Both failed before the fix and pass after.

**M2.** In `controlString(_:)` BEL is checked before the escape-state branch, so it ends the string in either state; backslash ends it after an ESC; another ESC stays; any other byte returns to the string. The comment says so. Tests: `a ESC <i> before ESC BEL b LF` yields `ab` for `]`, `P`, `X`, `^` and `_`, five rows of the removed-sequence table; all five failed before and pass after.

**M3.** `commit()` appends the line and calls `evict()`, which drops from the top while the lines exceed 10,000 or the retained bytes exceed 10 MiB, counting into the feed's running `dropped`. An evicted line is replaced in place by an empty `Line` so its text is released at once, behind a `head` index; the array is compacted every 10,000 evictions and at feed end, so eviction stays O(1) per line. `feed` keeps a final `evict()` for the line in progress growing since the last commit, then compacts both. `Change`'s contract is unchanged. Test: one 50 MB feed of 500,000 lines returns 10,000 committed, 0 evicted, 990,000 retained bytes and the same `lines` as 16 KiB feeds, and the test process's resident size across that one feed grows by less than 32 MiB, read from `mach_task_basic_info` with the input allocated before the first reading and `malloc_zone_pressure_relief` called before it, so freed pages from earlier tests do not mask growth. Before the fix the growth was 74.3 MB and 77.2 MB in the builder's two runs; after it 1,589,248 bytes in the orchestrator's full run and 1,638,400 in each of three suite runs. The orchestrator added one assertion: both readings are nonzero, since a failed kernel call returns zero and a bound on nothing proves nothing.

**S1.** The tests above. Two test-only choices by the builder beyond the spec's wording, both accepted: the Transcript suite is now `.serialized` (it was not; the spec assumed it, and the resident reading must not see another test's allocations), and the pressure relief before the first reading (without it the old code passed with −20 MB growth, the feed reusing pages earlier tests had freed). The three new ceiling tests sit in an extension of the suite struct for SwiftLint's 300-line body limit. `import Darwin` in the test file for the kernel calls.

**Cost recorded for the replan.** Serializing the suite takes the core test run from 16 s to 72 s, the four 50 MB streaming tests no longer running in parallel. The alternative, a separate serialized suite for the resident reading alone, would run in parallel with the others and read their allocations; the time is the price of a reading that means something.
