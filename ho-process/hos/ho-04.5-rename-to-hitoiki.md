# ho-04.5 — Rename to Hitoiki

The app is 一息. *Hitoiki* is the everyday reading, "a breather"; *issoku* is the on-reading the project was started under by mistake. The practitioner ruled the rename on 2026-11-04, placed it after ho-04x passed and before ho-04.6 and the replan week, and ruled on 2026-11-05 that the three Kamae files move with it and that the ho gets a review. This ho changes names and nothing else. No behaviour changes. No code changes beyond the name. The seed, the System Design, every closed ho, every review and every build-record entry keep "Issoku" as the historical name, and the README says so once.

## The invariant

After this ho, at its closing commit, these hold:

1. **The listed files carry the new name.** In every tracked file outside the protected set, the old name appears only where this spec allows it: once in the README's historical sentence, and in the overview's body and build record below its title. Everywhere else the substitution is exact and complete, in file names and in content: `IssokuCore` → `HitoikiCore`, `Issoku` → `Hitoiki`, `issoku` → `hitoiki`, `ISSOKU` → `HITOIKI`.
2. **The protected set is byte-identical.** Every file under `ho-process/hos/` as of the opening hash, every file under `ho-process/reviews/` and `ho-process/audits/`, the seed and the System Design (whose paths move and whose content, titles included, does not), `LICENSE`, `.swift-format`, `.swiftlint.yml`, `.pre-commit-config.yaml` and every test fixture: the same bytes as at `36e3785`.
3. **The code is the old code under the substitution.** The tree at `36e3785` with the four substitutions applied to the paths and contents of `Package.swift`, `Sources/`, `Tests/` and `scripts/` is identical to the new tree at those paths. No line is added, removed or reordered; no comment is reworded; no file is created or deleted.
4. **The stack is green with the same numbers.** The six verification commands pass before and after, with 43 app and 70 core tests, 0 failures, and the same coverage on both sets (95.75% on the core, 91.88% on the surface at the opening hash). A different count or a different percentage is a halt: it means something other than a name changed.

Every expected result below follows from these four. None follows from what the old tree happens to contain.
