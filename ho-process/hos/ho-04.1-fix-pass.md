## Problem

From `ho-process/reviews/ho-04x-report-1.md`, each confirmed by the orchestrator against the code at `19e3195d5e1804bc8430368b7aecff02de0927ca`:

- **M1.** `Transcript.feed` runs every byte of the input through the parser and only then trims the line in progress to 1 MiB; `commit()` takes the line as it stands. So an LF inside a feed commits a line longer than the cap, and the retained result depends on how the same bytes were chunked: 2,097,152 bytes and LF in one feed commit a 2,097,152-byte line, the same bytes in 1,024-byte chunks commit 1,048,576. Even at the pseudoterminal's chunk size, a full line plus 1,023 bytes and LF commits 1,049,599. Decision 3 says at most 1 MiB of the line in progress; Decision 1 says state carries across feeds, which means the result cannot depend on where the feeds end.
- **M2.** In the control-string state (OSC, DCS, SOS, PM, APC) an ESC moves the parser to the plain escape state, and from there any byte but a backslash returns to ground, so the rest of the string is drawn as text: `a ESC ] 0;before ESC 7 LEAK BEL b` draws `aLEAKb`. Decision 1 removes these strings up to BEL or `ESC \`. The comment beside the branch describes a backslash check the code does not make.
- **M3.** `Sources/Issoku/Theme.swift` at the range end has no `import SwiftUI`, no `Palette.color` and none of the eight `Theme.<token>: Color` accessors; the build commit `dd89260` removed them and nothing restored them. The practitioner ruled "keep" on 2026-11-03 and ho-04's Reflect says they were restored. They were not.
- **S1.** The ceiling tests read their limits from the model's constants, so widening a constant widens the assertion; the large-line tests never commit with an LF; the chunk-equivalence cases never cross a ceiling; the removed-sequence table has no ESC inside a control string. Together they pass M1 and M2.

Taken in from the same review: **N2**, two specified behaviours with no test (the scroll follows the end only when the end was in view, and `Command-C` through the window while Running copies the transcript so far), and **N3**, the test-target counts reversed in ho-04's Reflect and in the build record (61 core, 40 app, not the other way round). And **N1**: SGR 58 (underline colour) takes `5;n` or `2;r;g;b` arguments as 38 and 48 do, and the parser does not consume them, so `58;2;1;34;1` reads as bold blue. Decision 1 names 38 and 48 as consumed-and-ignored, not honoured; 58 joins that set and honours nothing new. The practitioner ruled it taken on 2026-11-04.

## Solution

**M1 — the per-line cap is enforced as bytes arrive.** Three places, one rule: `commit()` trims the line in progress to the cap before it commits; `feed` keeps its trim at the end; and `put` trims whenever the line in progress exceeds the cap by more than a fixed slack, a `static let` on the model equal to Run's 16 KiB read size with that reason beside it, so the trimming is amortised over the slack rather than paid per byte. Trimming stays whole characters, oldest first, with the cursor adjusted as now. After this the retained bytes of any feed are the same however the bytes were chunked, no committed line is longer than the cap, and the line in progress never holds more than the cap plus the slack at any instant. Tests, the report's three probes: 2,097,152 `x` and LF in one feed commit a line of 1,048,576 bytes; the same bytes in 1,024-byte chunks produce identical `lines` and the same retained count; a retained 1 MiB line followed by 1,023 bytes and LF commits 1,048,576.

**M2 — a control string ends only at BEL or `ESC \`.** One new parser state: in the control-string state an ESC moves to a control-string-escape state; there a backslash ends the string and returns to ground, another ESC stays (it may still begin the terminator), and any other byte returns to the control-string state with the string still open. The 256-byte bound keeps counting through it. The comment is rewritten to say what the branch does. Tests, the report's two probes: `a ESC ] 0;before ESC 7 LEAK BEL b LF` and `a ESC P before ESC 7 LEAK ESC \ b LF` both yield the one line `ab`; `ESC ] 0;t ESC \` still ends at the backslash; a control string longer than 256 bytes is still abandoned.

**M3 — Theme's accessors restored.** `import SwiftUI`, `Palette.color` and the eight `Theme.<token>: Color` accessors return exactly as they stand at `e08c5ea0be1ed6443a6327869dda6f39ba7cab0a` (`git show e08c5ea:Sources/Issoku/Theme.swift`); the "AppKit only" comment that replaced the import goes; the transcript table and the three derived tokens stay. The panel does not use them, which is the practitioner's ruling, not a finding. If the measured coverage set drops below the floor because of the unused accessors, halt and report; do not write a test whose only purpose is to call them.

**S1 — the tests pin the specified numbers.** The ceiling tests assert against literals, 10,000, 1,048,576 and 10,485,760, and the bound test against 256, not against the model's constants. The large-line tests end with an LF and assert the committed line's `byteCount`. One chunk-equivalence case crosses all three ceilings: the same bytes fed whole and in 1,024-byte chunks give equal `lines`, equal line in progress and equal retained count. The removed-sequence table gains the embedded-ESC cases of M2.

**N1 — SGR 58 consumed with its arguments.** `select()` treats 58 as it treats 38 and 48; the doc comment at the top of `Transcript.swift` names the three. Test: `ESC[58;2;1;34;1mx` yields `x` in the default style, and `ESC[58;5;1mx` likewise.

**N2 — two Panel tests.** Scrolling: fill the transcript past the cap, scroll to the top, append a chunk, and assert the visible rect did not move; scroll to the end, append, and assert the visible rect's bottom is the document's bottom. Copy while Running: a command prints `ready` and waits on `read -r`; with Running asserted, `performKeyEquivalent` with `Command-C` through the window; the pasteboard holds `ready` and a newline; the pasteboard is saved and restored as the other copy tests do.

**N3 — two marked corrections**, by the orchestrator, in ho-04's Reflect and the build record: 61 tests in IssokuCoreTests, 40 in IssokuTests, each marked `[corrected 2026-11-04, ho-04.1]`. Typographical by the forward-only rule's own exception; nothing else in either document changes.
