# ho-04.6 — The Escape ladder and the click-out rule

ho-04's run sheet found that the click that goes to paste a result into another app is the click that threw the result away, and that Escape, the key the hand reaches for to stop a command, did nothing while one ran. The practitioner ruled the Escape ladder on 2026-11-04 and placed this ho after ho-04.5. The Think phase of 2026-11-05 reshaped the ruling in four places, recorded below, and the result is simpler than the ruling: the panel has two axes that never touch. Visibility moves by the hotkey and by click-out, and moving it loses nothing. State moves by Escape and Stop, one layer at a time, and the layer that clears kills whatever is alive. The one exception on the first axis is that a running command is never hidden.

This ho revises closed documents and does not edit them. System Design 2.1 gets a dated amendment note at its end, pointing here, with its text left standing. ho-03 is not touched; the section "What this supersedes" names its decisions. The spec is a table. Every expected result is derived from it; it prescribes no recipe and no moment.

**Out of scope:** the Stop button and Control-C (unchanged); Quit (unchanged); the submission in flight (unchanged, ho-03.2's rule); history and recall (ho-05); any change to Run, Transcript, TranscriptView, Theme or the layout; any new control on the strip; any file under `Sources/HitoikiCore/`.

## Phase 1 — Think

Rulings of 2026-11-05, in the order they were made.

**Decision 1 — The hotkey is a visibility toggle, except while Running:** hidden, show; visible without the keyboard, take the keyboard; visible with the keyboard, hide. While a command runs the hotkey never hides the panel: with the keyboard it does nothing. (The practitioner first took "the hotkey steps the ladder as Escape does", then replaced it with the pure toggle and the Running exception. A hotkey that hid a running command was offered and refused twice: it is the background mode the System Design rules out.)

**Decision 2 — The ladder begins at Running.** In the gap between Return and Running, Escape, click-out and the hotkey leave the panel up, as ho-03.2 ruled. The gap is the spawn, milliseconds, unless Return is pressed in the first seconds after launch, before the environment capture finishes.

**Decision 3 — Click-out hides and keeps; it never hides a running command.** A click into another window, or Command-Tab, hides the panel in every state but Running, and everything on it stays: the result, the status, the retry offer, the line in the input. The next summons brings it back as it was. While Running the panel stays on screen without the keyboard; a click on the panel or the hotkey gives the keyboard back. (The ruling of 2026-11-04 had click-out dismiss only a clean panel and keep a typed panel on screen; the practitioner replaced both with hide-and-keep after walking the paste case: the result must not be lost, and a panel floating over the app being pasted into is in the way.)

**Decision 4 — Escape peels one layer: stop, clear, hide.** Running and not yet stopped: Escape stops the command exactly as Stop does. Running and stopped, Done, or a typed line: Escape clears the panel to a clean panel still on screen, killing the command if it is still alive. A clean panel: Escape hides it. The clear step clears everything — transcript, status, offer, the input's text — so a clean panel is one thing. (The ruling had the second Escape dismiss, hide and clear together; the practitioner split it into clear then hide, Spotlight's own two steps.)

**Decision 5 — Escape is an event of the panel, not a key of the command.** The Keystrokes table's row for Escape changes from `.ignore` to a new action, `.escape`, which Panel acts on by the ladder. Nothing is ever written to the pseudoterminal for Escape. Every route by which AppKit delivers Escape to the window — the input's field editor, the transcript's key handler while running, the transcript handing a key to the input when not running, the window's own fallback — reaches one function.

**Deferred to ho-05:** up-arrow recall of commands run since launch (session memory first; the history file is off by default), and a history control on the bar that drops the list. **Refused:** output history by scrolling (one command, one result is the product's shape), and a Clear button (Escape is the clear).

## Phase 2 — Execute

### Vocabulary

Six states, every one derived from facts Panel and its window already hold. No new stored state is added for the ladder; in particular no Escape counter. (Decision 5 of ho-03 still holds: `state: RunState?` is the one stored run state.)

| State | Facts |
|---|---|
| **Clean** | `state == nil`, no submission in flight, the input is empty |
| **Typed** | `state == nil`, no submission in flight, the input has text |
| **In flight** | a submission is in flight (Return pressed, Running not yet reported) |
| **Running, live** | `state` is `.running` and Stop has not been pressed since the command started |
| **Running, stopped** | `state` is `.running` and Stop, Control-C or Escape has stopped it (the `stopped` flag) |
| **Done** | `state` is `.done`, with the input empty or typed; the table does not distinguish |

Each state is also either **visible** or **hidden**, and a visible panel either **has the keyboard** (it is the key window) or does not.

Three moves, and the events that cause them:

- **hide** — the panel goes off screen; nothing on it changes. State, transcript, status, offer and input text are all kept.
- **show** — the panel comes on screen, placed on the mouse's screen if it was hidden, with the keyboard, as it was. A clean panel shows clean; a hidden Done panel shows its result.
- **clear** — the panel stays on screen and becomes Clean: `state` nil, the transcript empty, the status empty, the offer gone, the input empty, the keyboard in the input. If a command is alive when the clear happens, it is killed, and nothing of it reaches the panel afterwards.
- **take the keyboard** — a visible panel without the keyboard becomes the key window; nothing else changes.
- **stop** — exactly what the Stop button does today: the first stop since the command started interrupts the group, nothing more is drawn, the Stop count advances.
- **nothing** — no visible change, no process change.

### The table

Each cell is the result of the event in the state. Every cell has a test. A cell that says "nothing" is tested as "nothing": the panel's visibility, key status, `state`, transcript, status, input text and the process table are the same after the event as before.

| State | Escape | Click-out | Hotkey, hidden | Hotkey, visible, no keyboard | Hotkey, visible, keyboard |
|---|---|---|---|---|---|
| Clean | hide | hide | show | take the keyboard | hide |
| Typed | clear | hide, keep the line | show, with the line | take the keyboard | hide, keep the line |
| In flight | nothing | nothing; the panel stays | unreachable¹ | take the keyboard | nothing |
| Running, live | stop | nothing; the panel stays | unreachable¹ | take the keyboard | nothing |
| Running, stopped | clear, killing if alive | nothing; the panel stays | unreachable¹ | take the keyboard | nothing |
| Done | clear | hide, keep the result | show, with the result | take the keyboard | hide, keep the result |

¹ Nothing hides a panel with a submission in flight or a command running — the two click-out cells and the two hotkey-with-keyboard cells above say so, and the in-flight row inherits ho-03.2's rule — so a hidden panel is always Clean, Typed or Done. The three unreachable cells are not tested as cells; the invariant that makes them unreachable is tested (below).

Two columns are unchanged and listed so the table is whole:

| State | Stop / Control-C | Quit |
|---|---|---|
| Clean, Typed, Done | nothing | terminates at once |
| In flight | nothing | waits for the start, kills, terminates |
| Running, live | stop | kills, waits at most one second for Done, terminates |
| Running, stopped | kill | the same |

Quit reads one fact, "a command runs or a start is in flight"; it is the fact today's `canDismiss` reports, and it keeps that meaning under whatever name the builder gives it. Quit's tests are not rewritten.

### The invariants

Everything the table says follows from these. The builder restates, per handler, which of them the handler keeps and why.

1. **Nothing alive is ever hidden.** At every moment, if `state` is `.running` or a submission is in flight, the panel is visible. No event hides it.
2. **Hiding loses nothing.** After a hide and the show that follows, `state`, the transcript's text, the status, the offer and the input's text are what they were before the hide.
3. **A clear is total and final for the command it clears.** After a clear, the panel is Clean and visible with the keyboard in the input; no process of the cleared command's group is alive; and whatever Run reports about that command afterwards — its Done, its last chunks — changes nothing on the panel. The next summons after a clear-then-hide is a clean panel.
4. **A command submitted after a clear runs.** Run is free for the next line whether or not the cleared command's Done has arrived yet. When the kill's Done is absorbed, and whether the next start waits for it, is the builder's; what holds is that Return on a clean panel after a clear starts the typed line and the panel reaches Running for it.
5. **Escape never reaches the command.** No byte is written to the pseudoterminal for an Escape key, in any state, by any route.
6. **One function per event.** Every Escape, by every delivery route, reaches one function of Panel. Every click-out reaches one. Every hotkey press reaches one. The table is read from the six states' facts inside those functions, nowhere else; the window keeps no copy of any of them.
7. **Stop is one thing.** The stop that Escape performs is the same call the Stop button and Control-C make: the same counter, the same `stopped` flag, the same "nothing more is drawn".

The subtle cell is Escape in Running-stopped racing Done. The command was interrupted; its Done may arrive before the second Escape, after it, or during the clear. Invariant 3 holds in all three orders: the panel is Clean afterwards and nothing of the command lands on it. The test for the cell holds the command at a readiness point that ignores SIGINT (a trap, as `stopTwice` does), so the second Escape finds it alive and must kill; a second test lets Done land first, so the second Escape finds Done and clears. The spec does not say when to check anything.

### Tests

The harness tests every cell of the table through Panel's event entries — the Escape function, the window's resign-key path, `toggle()` — against a real `PanelWindow`, as the Panel suite does today. Specifically:

- **Every cell of the five-column table** that is not unreachable: 27 cells. Each asserts the result in the vocabulary's terms (visibility, key status, `state`, transcript text, status text, offer, input text, and for the kill cells the process table through `survivors(ofGroup:)`). Cells may be grouped into parameterised tests where the state is the parameter and the event and result are the same; a grouped test still names each cell in its description.
- **Invariant 1** as its own test: from In flight, Running-live and Running-stopped, every hiding event (click-out, hotkey with the keyboard) is attempted and the panel is visible after each.
- **Invariant 2** as its own test: a Done panel with a typed line is hidden and shown, and everything is as it was.
- **The race**, two tests, as described above.
- **Invariant 4**: clear a live command, submit a new line at once, reach Running for it.
- **Every Escape route once**: an Escape key event delivered to the input's field editor (Clean: hides), to the transcript while Running (stops), to the transcript when Done (clears), and `cancelOperation(_:)` on the window with no text responder (hides). The `key(_:code:modifiers:in:)` helper and `kVK_Escape` exist for this.
- **The keystroke table**: the Escape row of `KeystrokesTests` changes from `.ignore` to `.escape`; the count of rows does not change.
- **Invariant 5**: a command that reads a line gets nothing from an Escape and sees a length of zero on Return — the `keystrokes` test's shape.

Existing Panel tests whose expectations the table changes are rewritten to the table, not deleted: `composing`, `runningIsUndismissable`, `inFlightIsUndismissable`, `dismissalBeforeRunning`, `dismissalClearsOffer`, `dismissalClears`, `cursor`, `layout` and `outputBeforeDone` all exercise `dismissIfAllowed()` or `toggle()` with the old results. Their names change with their meaning. No test is removed.

Nothing in `Tests/HitoikiCoreTests/` changes; the core count stays 70.

### Witnessed live only

The harness cannot show another app taking the keyboard or the system delivering the hotkey. The practitioner's run sheet, after the harness is green, in the rebuilt app:

1. Hotkey, type a line, do not press Return, click into another app: the panel hides. Hotkey: it is back with the line. Click on the panel's input: it has the keyboard.
2. Hotkey, `uptime`, Return, Done. Command-Tab away: the panel hides. Hotkey: the result is back. Escape: clean. Escape: hidden.
3. Hotkey, `sleep 30`, Return. Click into another app: the panel stays, without the keyboard. Hotkey: it has the keyboard. Hotkey again: nothing. Escape: `running` ends with Stop's status. Escape: a clean panel. Escape: hidden. Nothing in `ps` for the sleep.
4. Hotkey, `sh -c 'trap "" INT; sleep 300'`, Return. Escape, Escape: clean panel, and `ps` shows no sleep.
5. Hotkey, `uptime`, Return, Done. Gear, Settings…: the panel hides (the Settings window took the keyboard). Hotkey: the result is back.
6. Hotkey, Return on `ssh host-d 'sudo true'`, Done with the offer. Click away, hotkey: the offer is still there; Return takes it.

### What this supersedes

- **System Design 2.1**, "Escape and click-out do nothing" in Running and "Escape or click-out hides the panel" in Composing and Done: superseded by the table. "Nothing survives the panel" stands and is now true at every exit. "Escape and click-out never kill a running process; they are the accident paths and are inert while Running": superseded for Escape, which is a deliberate three-step path; confirmed for click-out, which never kills and never hides a running panel. "There is no background mode": stands, by invariant 1.
- **ho-03 Decision 5**, `canDismiss` as "the one rule every dismiss path reads": there is no dismiss any more; the fact survives for Quit alone.
- **ho-03 Decision 6**, the three dismiss paths through `dismissIfAllowed()`: superseded by the three moves. The hotkey "toggles like Spotlight" survives as Decision 1 above.
- **ho-03 Decision 8**, the Escape row `.ignore — Decision 6`: now `.escape`.
- **ho-03 Decision 17**, "every summons starts clean": narrowed to every summons after a clear. A summons after a click-out shows what was there.
- **ho-03 Reflect, point 1**, the click-out as `resignKey()`: the mechanism survives; what it does is the table's.
- **The ruling of 2026-11-04** in ho-04's Reflect: reshaped by Decisions 1, 3 and 4 above; its text stands there as history.
