## Findings

### Must fix

- M1 — `Sources/Hitoiki/Panel.swift:214` — Clear can leave members of the cleared command's process group alive, after which Escape or click-out can hide them. For `sh -c 'trap "" HUP INT; echo ready; sleep 30' & wait`, the first Escape can terminate the outer shell while the inner shell and sleep survive in its group; the second Escape can find Done and clear without issuing any kill. If it instead finds Running after the shell was reaped, the queued `run.kill()` also does nothing because `Sources/HitoikiCore/Run/Run.swift:199` rejects signals once `child.exit` exists. This violates invariant 3's empty-group requirement and the prohibition on hiding a live command (`ho-process/hos/ho-04.6-escape-ladder-and-click-out.md:109`, `:90`); see the local evidence under the third ho-specific question.
- M2 — `Tests/HitoikiTests/PanelTests.swift:1256` — `escapeClearsKilling` does not establish that the cleared command's Done has been consumed while the panel remains Clean, so it can pass after an incorrect transient restoration of that Done. Group disappearance does not acknowledge Panel's state-stream consumer; after the last Clean assertion at `:1263`, an incorrect Done can update the panel and then be replaced by the next command's Running and Done before `done()` polls again (`:198`, `:215`, `:1264`). The final transcript and status assertions would then pass. The Running-stopped × Escape cell lacks a conclusive test of the late-Done clause required by the spec at `:109`, `:115`, `:121` and `:124`; four previously reported mutation failures do not exclude this passing schedule.
- M3 — `Sources/Hitoiki/Panel.swift:92` — Showing a hidden panel discards a start-failure status because `show()` calls `apply()` without the failure that produced the displayed strip. A failed initial start leaves `state == nil` and the typed line intact (`:144`–`:149`); hide keeps the displayed error, but the next hotkey rebuilds an empty status and hides the output card (`:265`, `:280`). The Typed hide/show tests construct no failure status, so their before/after comparisons miss this case (`Tests/HitoikiTests/PanelTests.swift:336`, `:1190`). This violates hide/show's preservation of status and invariant 2 (`ho-process/hos/ho-04.6-escape-ladder-and-click-out.md:70`–`:71`, `:108`); the failure path was traced in source without forcing resource exhaustion.
