## Findings for ruling

### F1 — Quit can skip the kill queued by a clear
- Where: Sources/Hitoiki/App.swift:92; Sources/Hitoiki/Panel.swift:63,277,290,296,298; Tests/HitoikiTests/PanelTests.swift:798,1288
- Kind: bug
- Grade: 1
- Behaviour: changes: quitting immediately after a killing clear completes the command's kill before the app terminates.
- Finding: A clear queues `run.kill()` in a Task and immediately sets `state` to nil, which makes `isBusy` false while `cleared` still records an unfinished command. A termination request in that interval returns `.terminateNow`; `killForQuit()` would also return at its `isBusy` guard, so the queued SIGKILL need not run before the app exits. The existing quit tests cover Running and submission-in-flight, and the clear test yields before checking the process table; neither covers this interval.
- Change: Have the termination decision and quit cleanup account for the existing awaited-cleared-Done fact, and finish sending the kill on that path. Add a regression that requests termination directly after the killing clear, preserving the clean panel's existing hide rules.

### F2 — An older update reply can replace a newer release
- Where: Sources/Hitoiki/UpdateCheck.swift:175,183,211,220,222; Tests/HitoikiTests/UpdateCheckTests.swift:369,386
- Kind: bug
- Grade: 1
- Behaviour: changes: the update line retains the newest release already found when overlapping replies arrive out of order.
- Finding: An automatic check and a manual check may overlap because only manual checks are excluded by `checking`. If an older request obtains release 1.1 but completes after another request has recorded release 1.2, its unconditional assignment replaces `available` with 1.1, despite that property's promise to hold the newest release found. The tests exercise overlapping manual calls and later failures, but no pair of differently versioned replies arriving out of order.
- Change: Update `available` only when the found release is newer than the version already retained, while keeping each manual check's own answer. Add an out-of-order automatic/manual response test.

### F3 — A failed history test can leave a callback pointing at a released watcher
- Where: Tests/HitoikiTests/HistoryTests.swift:217,222,227,228,528,533,555,562
- Kind: bug
- Grade: 1
- Behaviour: changes: a failing file-event test releases its event stream and cannot leave a callback accessing a destroyed Watcher.
- Finding: The stream stores an unretained pointer to `Watcher`, but `rewriteLeavesOneFile()` stops it only after its throwing wait succeeds. If that wait throws, the watcher can be released while the active stream still holds its pointer; a subsequent file event dereferences it. A failure after stream creation during initialization also has no stream-release path.
- Change: Make stream cleanup unconditional after acquisition, including failed initialization, and keep the watcher alive until queued callbacks have finished. Preserve the file-replacement witness and its assertions.

### F4 — Failed release builds leak their temporary directories

- Grade: 1
